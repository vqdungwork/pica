Approvals: the design system

Revised 2027-01-22. Built at 1440 x 900, 768 x 1024 and 375 x 812. Sample data, no database, no live API. Every token and every component with all its variants and states, which is what pica's step 3 asks for: the kit is built before any screen, so a screen cannot introduce a value the system does not have.

Every value here comes from shared.css, the same stylesheet the boards and the interactive flow load. There is no second copy, so this page cannot document something the screens do not use.

Type, by role

Roles, never bare sizes: 16px is body here and a caption somewhere else, so a list of numbers characterises nothing. numerals.tabular is asserted, because the age column is the content and proportional figures do not line up.

Radius and elevation

radius.max: 8 is asserted and --r is 8px, one value. There is no elevation: a ledger is flat, and every shadow is a hue spent on decoration.

--r: 8px

Components, with every variant and state

Button

Primary at 40px, secondary in a bar at 32px. control.height.min: 32 is asserted, so neither can shrink below it: 24px controls on a screen somebody works in all day is what the assertion exists to prevent.

Row, the unit the whole product is made of

31Ridgeway Metals Ltd
4Ash Lane Dairy
2A payee with a very long registered legal name indeed, Limited

The third row is the state that matters. A 64-character legal name is in the test data by name, and the name cell wraps rather than truncating, because a truncated payee on an irreversible transfer is the sector's own defect and no ellipsis rule exists in this token set to cause it.

A fee of zero renders as 0.00 and never as blank or absent. The sector forbids hiding a fee behind a disclosure, so the row has no collapsed state at any viewport and a unit test asserts it.

Tab bar

The current tab is the one that owns the visible screen, not the one last touched. Inside a task the bar is hidden entirely, because a task is not a place.

The empty state says what would appear and does not read as loading. That was a recorded defect, D-04, with a test that failed first.

What nothing here checks

No check reads this file. pica.md has asked for it since step 3 and html-prototype.md names it, and the only script that mentions it is the capture producer, which excludes it. So this page is a rule with no executable behind it, which is the class of gap this project keeps finding in itself, and it is recorded here rather than left for somebody to notice.

What would close it: a check that every token in tokens/tokens.json appears on this page, and that every class used by a screen appears here with at least one variant. Until that exists, a component can enter the product without ever being documented, and nothing will say so.
